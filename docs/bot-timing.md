# Bot 动作节奏

线上 bot 在每次动作提交前独立随机等待。最终区间由动作基础窗口和人设的
`decisionLatencyMs`（L）共同决定，单位为毫秒：

- 下限 = 动作基础下限 + 0.6 × L
- 上限 = 动作基础上限 + 1.4 × L
- 在区间内均匀随机抽样并取整。

| 动作 | 基础窗口（毫秒） |
| --- | --- |
| 开始游戏 | 1500–2500 |
| 抽牌堆 | 1200–2000 |
| 抽弃牌堆 | 1500–2500 |
| 替换手牌 | 1800–3000 |
| 错配落位 | 1800–2800 |
| 弃牌 | 1500–2400 |
| 查看自己 | 1500–2500 |
| 查看对手 | 1800–3000 |
| 交换 | 2200–3500 |
| 跳过技能 | 1200–2000 |
| 宣告 Cabo | 2000–3200 |
| 下一轮准备 | 3000–4500 |

人设 L：记忆大师 200、赌徒阿豪 400、搅局者 600、算盘 700、月神 900、
佛系老王 2200。例如抽牌时，记忆大师等待 1320–2280ms，佛系老王等待
2520–5080ms。启用人设抖动时，L 会按既有规则在进程初始化时抖动一次。

所有线上预设均保留至少 1.2 秒的基础反应窗口。剩余回合时间不足时，驱动
沿用截止预算保护缩短等待，为提交留出安全余量。等待后重新核对局面，过期
动作不会提交；停止 bot 后也不会继续提交等待中的动作。

自定义人设的 L 为 0 时仍保留动作基础窗口。协议测试可显式设置驱动的
`skipDelays: true` 跳过等待；实际对局默认关闭该选项。停止驱动会取消等待定时器。
实现见 `packages/bot/src/plans.ts` 中的 `ACTION_DELAY_RANGES` 和 `decisionDelayRange`。
