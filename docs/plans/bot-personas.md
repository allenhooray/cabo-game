# Cabo Bot 陪玩能力设计：数学模型 + 规则策略 + 人格参数化

本文回答两件事：

1. 能否用**固定数学模型 + 策略规则**（而非机器学习）实现可用的 Cabo bot，可行性与局限在哪里。
2. 如何设计一组**可调参数**，把参数取值映射为人格维度，从而生成若干差异化人设，并给出每种人设的配置、特征与适用场景。

结论先行：**可以，而且 Cabo 属于"规则 bot 能做得相当好"的少数派**。原因是它信息结构清晰、行动空间小、结算确定、随机性来源单一（只有洗牌）。真正做不好的是"像人"而不是"强"——拟人化只能靠参数抖动和节奏表演来近似。

> **状态：已按技术方案落地并回填实测数据。** 本文的公式与结论都保留了推导过程，包括**一处被实测推翻的推导**（§2.2 的 Cabo 阈值漏掉了 `δ`）和**七个把校准带偏的建模坑**（§5.6.1）。落地结论见 §9.1：校准误差 **2.7%**（门槛 5%），M4 通过（8.3 倍），M5 通过（**71.9%**，门槛 70%）——但 M5 的达标依赖采样数 ≥ 400，这本身就是一条结论。

## 一、为什么 Cabo 适合规则策略而非机器学习

从 `packages/shared/src/engine.ts` 的实现可以直接读出这几个性质：

| 性质 | 代码依据 | 对 bot 的意义 |
| --- | --- | --- |
| 状态完全可枚举 | 牌组固定 52 张（`deck.ts`：A–Q 各 4 张、两张 K、两张王），暗牌只在服务端引擎里 | 可以精确做"未见牌池"计数，不需要近似 |
| 行动空间极小 | `legal-actions.ts`：每阶段合法动作 ≤ 4 类，`replace` 用选择描述符而非枚举组合 | 不需要搜索树，规则决策树就够 |
| 结算确定 | `scoreRound()`：手牌分是确定求和，Cabo 判定是确定的大小比较 | 唯一的不确定性来自未知牌，不是规则本身 |
| 单局随机源唯一 | `shuffle(createDeck(), random)` | 未知牌可用均匀先验精确建模，蒙特卡洛收敛很快 |
| 回合制、无实时压力 | `turnDurationSeconds` 默认 60s | 有充裕算力做采样，不需要查表或蒸馏 |
| 无自然语言、无谈判 | 动作集里没有协商类动作 | 不需要 LLM，规则引擎即可 |

换句话说：**Cabo 的不确定性是"信息不完全"，不是"策略空间爆炸"**。前者可以用概率建模 + 采样解决，后者才需要机器学习。这里恰好只踩中前者。

## 二、可行性分析

### 2.1 三个层次，逐层可行

**信念层（Belief）——完全可行，可精确。**
`client-core/src/knowledge.ts` 已经实现了位置级知识追踪（`slots` / `opponents[].slots`），并且 assisted 模式下服务端在重连时会恢复快照。bot 只需要在此之上补一个**未见牌池计数器**（记录所有已公开或已私密看到过的牌，从 52 张里扣除），就能得到每个未知位置的精确后验分布。

**评估层（Evaluation）——可行，且存在闭式解。**
手牌期望分可以解析计算；Cabo 宣告的最优阈值有闭式解（见 §3.3），不需要迭代搜索。

**策略层（Policy）——可行，规则化。**
决策可以写成一条条优先级规则：先判断能否安全多张替换 → 再比较抽牌来源的期望收益 → 再判断能力牌的价值 → 最后判断是否宣告 Cabo。这套规则是确定性的、可审计的、可单测的。

### 2.2 关键可行性证据：Cabo 阈值有闭式解

设本回合宣告 Cabo 时我的手牌最终分为 `H`，宣告成功的概率为 `P`。规则（`scoreRound()`）是：宣告者严格最低得 0 分，否则手牌分 `+5`。

**第一版推导（有错，保留在此以记录修正过程）：**

- 宣告：期望得分 `(1 − P)·(H + 5)`
- 不宣告：期望得分 `H`

令两者相等，解得 `宣告 Cabo ⟺ P > 5 / (H + 5)`。

**这个推导错在第二行。** 不宣告 Cabo 的人**不吃 `+5` 惩罚**——他的回合分就是最终手牌分 `H_final`。而继续打下去手牌分平均会更低（对手会换牌、自己会塌缩同点），所以 `E[H_final] < H`。正确的不等式是

```
宣告：  (1 − P)·(H + 5)
不宣告：E[H_final] = H − δ,   δ = H − E[H_final] > 0
```

令两者相等：

```
宣告 Cabo  ⟺  P(严格最低) > (5 + δ) / (H + 5)
```

漏掉 `δ` 的后果不是"稍微激进一点"，而是**灾难性的**。用实测的 `δ(H)`（300 局、11.1 万个未宣告观测点，工具见 `packages/bot/src/harness/continuation.ts`）：

| 当前手牌分 H | 实测 δ | 修正后门槛 (5+δ)/(H+5) | 旧公式 5/(H+5) |
| --- | --- | --- | --- |
| 1.44 | −2.69 | 0.359 | 0.776 |
| 7.16 | 0.08 | 0.417 | 0.411 |
| 13.85 | 4.04 | 0.479 | 0.265 |
| 22.67 | 9.04 | 0.507 | 0.181 |
| 29.02 | 13.65 | 0.548 | 0.147 |
| 35.54 | 20.11 | 0.619 | 0.123 |

`H ≈ 26`（四张未知牌的期望手牌分）时旧公式给 0.147，**低于**四人桌"手牌一张都没认出来"时 `p̂` 的下限约 0.25 —— 于是 bot 会在**回合第一手就宣告 Cabo**。这是实现阶段第一个被实测揪出来的错误。

实现里把 `δ` 拟合成 `δ(H) = max(−2.7, 0.62·(H − 6.8))`。注意 `δ` 在小 `H` 端是**负**的：手牌已经很低时，继续打下去反而会被对手的 11/12 换牌抬分，所以"手牌很好"不等于"越等越好"，反而更该锁定。

这条式子仍然极其重要：它把一个"什么时候该喊 Cabo"的策略问题压缩成一个**单参数族**——在 `P*` 上乘一个谨慎系数 `k`，`k` 就完整刻画了 bot 的风险性格。人格参数化因此有了干净的数学支点。

注意两个前提修正：
- `H` 应理解为"当前手牌的期望分"（已知牌精确、未知牌按池均值），`δ` 负责把它折算到最终分。
- 多人局下 `P` 是"严格低于**所有**对手最终分"的联合概率，不是两两概率，必须用蒙特卡洛估计（见 §5.6）。**注意是严格低于**：平局算输。

### 2.3 参考牌值基线

52 张牌总点数和 338，均值 6.5。因此：

- 四张未知牌的期望手牌分 = **26.0**，标准差 ≈ 7.3（20 万次采样）。
- 一个不做任何信息利用的 bot 会永远停在 `H ≈ 26`，对应 `P* ≈ 16%`——而 4 人局里随机玩家严格最低的概率只有约 25%，也就是说它**有能力喊但不该喊**。这个对比说明：光有阈值公式不够，`P` 的估计质量才是强度上限。

## 三、局限与边界（诚实清单）

必须承认的局限，按影响程度排序：

**1. 游戏本身几乎没有欺骗空间，bot 会很快逼近最优。**
Cabo 没有 bluff 机制——你不能"诈"一张牌，因为分数是算出来的。这带来一个反直觉的后果：**规则 bot 越接近最优，就越无聊**。所以"陪玩 bot"的核心难点不是强度，而是**故意保持在一个舒适强度区间**。这也意味着必须保留 `ε`（失误率）这类参数，否则 bot 会强到没人愿意玩。

**2. 对手模型只能用均匀先验，会系统性低估对手。**
bot 假设"对手未知牌服从未见牌池的均匀分布"。但真实对手会把好牌留下、坏牌换掉，所以他们的真实手牌分**低于**均匀假设。这会让 bot 高估对手强度，从而**过于保守地推迟 Cabo**。缓解办法：给对手的未知牌估计乘一个"理性折扣"（例如 `μ_opponent = 0.88 × μ_uniform`），折扣本身作为一个参数。

**3. 信息泄露通道只有两条，且都可被反向利用。**
`replaceHeld()` 会把被替换掉的牌推进弃牌堆并广播 `discard` 事件；`exchange-mismatch` 会公开所选的全部牌。bot 可以据此推断对手留了什么——但对手同样能从 bot 的弃牌里推断 bot。参数里要有"是否利用对手弃牌"的开关，否则容易变成单向透明。

**4. Shooting the Moon 的投入产出比极低。**
需要手牌恰好 2 张 Q + 2 张 K。全牌组只有 2 张 K，发牌时同时拿到两张 K 的概率 0.45%，再恰好含两张 Q 的概率 0.49%，自然触发概率约 **0.0022%**。它只能靠主动"囤牌"去工程化实现，成功率低、周期长。适合做彩蛋人设，不适合做主力策略。

**5. 参数空间大，手调容易过拟合。**
6 个人设 × 13 个参数 = 78 维。纯手调必然过拟合到开发时的少数对局。必须配自对弈回归（§5）。

**6. 固定参数会被玩家摸清。**
长期对局里玩家会学会"这个 bot 只在 H ≤ 12 时喊 Cabo"。缓解：每局开局对参数做 ±15% 抖动，并把抖动种子暴露在日志里以便复盘。

**7. 拟人化本质是表演。**
`ε` 失误率是伪装的，决策延迟也是伪装的。高水平玩家仍能从"从不犹豫、从不聊天、决策时间恒定"看出是 bot。所以拟人化要做在**节奏层**（延迟抖动、聊天、偶尔的无意义动作），而不是只做在策略层。

**8. 不能扩展到规则复杂度更高的模式。**
如果未来加入协作、交易、非确定性结算等机制，规则策略会迅速退化，届时才需要引入学习。当前 v7 协议下不必要。

## 四、参考架构（贴合本仓库）

```
packages/bot/                     ← 新增包，依赖 shared + client-core
  src/
    belief.ts      未见牌池计数 + 位置后验（复用 knowledge.ts，补 unseen pool）
    evaluate.ts    期望手牌分 / 蒙特卡洛胜率 / 动作收益评估
    policy.ts      规则决策树（纯函数，输入 state + persona → 输出 action）
    persona.ts     BotPersona 参数结构 + 预设表 + 抖动
    driver.ts      JSONL 接入 cabo-agent（协议 v7）
```

接入方式有两条路，**推荐第一条**：

**（推荐）作为独立玩家进程接入。** 直接复用 `cabo-agent` 的 JSONL 协议 v7（见 `docs/agent-protocol.md`）：读 `observation`（含 `legalActions`、`knowledge`、`caboRisk`），写 `action`。好处是 bot 与真人走完全相同的通道，天然公平。

**（不推荐）服务端内嵌。** `CaboRoom` 能直接拿到引擎，写起来更省事，但 `engine.debugHand()` 会暴露暗牌——一旦 bot 用了它，就是作弊。现有实现说明里明确写了"未加入 bot takeover"，请保持这个边界。

**硬性约束：** bot 只能从 `observation.knowledge` 和公开事件获取信息。任何直接读取服务端暗牌的实现都应视为 bug。

另外，`caboRisk` 字段（`strictLowest` / `tieFails` / `failurePenalty` / `knownScore` / `unknownCount`）已经由服务端算好并下发，bot 可以直接作为阈值公式的输入，不必自己重算规则常量。

## 五、核心数学模型

### 5.1 未见牌池

维护一个 `unseenPool: Map<rank, count>`，初始为牌组全量（1–12 各 4 张、K 两张、王两张），然后扣除：

- 自己已知的手牌（`knowledge.slots`）
- 已偷看到的对手牌（`knowledge.opponents[].slots`）
- 所有公开弃牌（`discard` 事件、弃牌堆顶）
- mismatch 公开的牌

对任意未知位置，`P(该位置是 r 分牌) = unseenPool[r] / Σ unseenPool`。

### 5.2 手牌期望分

```
E[H] = Σ_{已知位置} rank + Σ_{未知位置} E[rank | unseenPool]
```

`E[rank | unseenPool]` 就是未见牌池的加权均值。注意手牌数会因错配罚牌而 > 4（`resolveMismatch` 可能插入两张），公式要按实际 `cardCount` 走。

### 5.3 Cabo 宣告判定（核心）

```
p̂  = MonteCarloWinProbability()          # §5.6
Ĥ  = E[当前手牌分]（已知牌精确 + 未知牌按池均值）
δ  = max(−2.7, 0.62·(Ĥ − 6.8))           # 实测的"继续打能降多少分"
k   = persona.cautionFactor × 局势修正
宣告  ⟺  p̂ ≥ k · (5 + δ) / (Ĥ + 5) · 活性兜底
```

局势修正（`scorePressure`）：

```
k_eff = clamp( k_base · (1 − catchUpGain · (myTotal − minRivalTotal) / targetScore),
               0.3, 4.0 )
```

含义：自己总分落后越多，`k` 越小（越敢赌）；领先时 `k` 越大（越保守）。

**活性兜底**（实现阶段新增，非数学推导）：引擎**没有回合上限**——牌堆空了会把弃牌堆重洗回牌堆（`ensureDeck`），所以一轮可以无限进行。全员保守时它就会真的无限进行（实测阈值放大 1.5 倍后 **86% 的对局卡在步数上限**）。真人局里总会有人先忍不住，机器人必须自己造出这条退出路径。做法是本轮回合数超过 24 之后把门槛线性下调，到 60 回合压到 0.35 倍。正常一轮约 12–16 回合，所以宽限期内不生效，校准结论不受影响。

### 5.4 抽牌来源选择

- **抽弃牌堆**：已知牌面，但**必须**替换（`discardHeld()` 只允许 deck 来源的牌被弃掉）。收益 = `最高已知手牌分 − 弃牌堆顶分`。仅在为正且超过阈值时选择。额外要考虑"把高牌推进弃牌堆 = 送给下家"的泄漏成本。
- **抽牌堆**：未知，但有两条出路——替换，或直接弃掉（若点数 7–12 则触发能力）。因此抽牌堆的期望收益 = `max(替换收益, 弃牌收益 + 能力价值)`。

### 5.5 能力牌价值（7–12）

从 `discardHeld()` 与 `POWER_PENDING` 分支可读出：

| 点数 | 能力 | 收益模型 |
| --- | --- | --- |
| 7 / 8 | 看自己一张 | 信息价值 = 降低一个未知位置的不确定性，等价于把该位置的方差消掉 |
| 9 / 10 | 看对手一张 | 信息价值，且可被后续 swap 兑现 |
| 11 / 12 | 交换双方任意位置 | **净收益 = 2 × (对手牌分 − 自己牌分)**，因为分差变动是双倍的 |

11/12 是全游戏单步收益最高的动作（可以一次性把分差拉开 2×差值），但**前提是知道对手那张牌的点数**。所以 9/10 偷看 → 记住 → 11/12 精准交换，构成一条明确的两步规则链，是规则 bot 最值得投入的组合。

### 5.6 蒙特卡洛胜率估计

`p̂` 用采样而非解析：

1. 用未见牌池随机填充所有未知位置（自己的 + 对手的）；
2. **给每个对手跑一次"最终回合"**（`FINAL_TURNS` 的语义：宣告后每个对手各打一回合）；
3. 对每个玩家求和得到手牌分；
4. 判断"我是否严格低于**所有**对手"（平局算输）；
5. 重复 N = 200–500 次，取频率。

复杂度 O(N × 玩家数 × 手牌数)，单次决策 < 1 ms，完全可接受。

### 5.6.1 校准：七次把模型带偏的坑

第一版模型看起来"就是上面那四步"，实测校准误差 **29.5%**。逐个修到 **2.7%** 的过程中，发现七个纯靠读代码看不出来的建模错误。它们的共同点是：**偏差方向一致、幅度不大、不抛异常**——只有把"模型预测量"和"回合实际量"并排打印（`harness/diagnose.ts`）才看得见。

| # | 坑 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | 被替换掉的牌留在未见池里 | 对手被系统性高估（被换掉的通常是大牌） | `applyPublicAction` 把 `discardedCards` 推进弃牌堆 |
| 2 | 我方终局分也乘了对手理性折扣 `ρ` | 自己手牌分被低估约 1.6 分 | `ρ` 只作用于对手 |
| 3 | 对手最终回合抽牌回落到"期望值"小数 | 永远抽不到 11/12，换牌能力凭空消失 | 抽不到就抽不到，不许编造中间值 |
| 4 | 对手换牌的目标写死成"我" | 凭空给我加 2.1 分伤害（实测只有 0.5） | 在所有玩家（含其他对手）里挑最低牌的那家 |
| 5 | 未知位置按池均值抽 | 模型对手均值终局分 13.85 vs 实际 11.43 | 用"被换过"这个公开信息做**上界**（`slotBounds`） |
| 6 | 牌堆和手牌共用一个池 | `deckCount = 0` 时对手照样能抽牌换牌 | 拆成两个池，牌堆那堆**正好** `deckCount` 张 |
| 7 | 弃牌堆重洗回牌堆时不清空自己的弃牌堆记录 | 池子凭空少掉最多 13 张，未知手牌位填不满、回落到池均值 | 维护恒等式 `池 = 牌堆 + 未知手牌位`，不足就从最老的弃牌还回去 |

第 5 和第 7 条最值得记：

- **第 5 条**：对手整轮都在"用低牌换高牌"，而"这个位置被换过"意味着新牌 ≤ 被换掉的旧牌，旧牌是**公开的**。不做这个上界，对手均值终局分被高估 2.4 分。
- **第 7 条**：`ensureDeck` 的重洗**不发事件**。缺口精确等于重洗张数（重洗前 `池 = 牌堆 + 未知位`，重洗后服务端牌堆多了 `弃牌堆 − 1` 张而 bot 的池子没变）。实测 **10.6% 的抽样**出现缺口、最大 13 张。修掉之后校准误差 3.5% → **2.7%**，高 `p̂` 段偏差 −14.2% → **+0.7%**。

### 5.6.2 对手理性折扣

- 对手未知牌乘理性折扣 `μ_opponent = ρ · μ_uniform`（`ρ` 默认 0.88，由 `countingSkill` 缩放），修正"均匀先验会高估对手"的系统性偏差；
- 对手的最终回合按**最优单步**建模（换最高分 / 同点塌缩 / 摸到 11·12 就换牌），两条路互斥取更优。

### 5.7 同点塌缩：全局最强的得分手段

这是 `engine.ts` 里最容易看漏、但影响最大的一条机制。`replaceHeld()` 中：

- 被选中的 k 张牌里，**只有 `replacementPosition` 那一张**被替换为持牌，其余直接从手牌移除并进入弃牌堆；
- `matches` 只校验**被选中的牌彼此同点**（`selected.every(c => c.rank === selected[0].rank)`），**与持牌点数无关**。

```
手牌 [12, 12, 5, 3]，选中位置 1、2，持牌为任意点数 X，落点选 1
结果 [X, 5, 3]        // 4 张 → 3 张，手牌分 −24 + X
```

推论有三条，都必须写进策略：

1. **囤同点已知牌 → 一次性塌缩**是比"换低牌"更本质的获胜路径，因为它同时降低分数**和减少手牌张数**。4 张变 3 张意味着终局少算一张牌，期望收益约等于一张牌的期望分。
2. **多张替换的收益与持牌好坏无关**，所以哪怕抽到一张烂牌，只要手里有已知同点对，塌缩就是正收益。
3. 因此评估函数必须**对"手牌张数减少"单独计价**，形如 `收益 = ΔE[H] + λ · Δ手牌张数`。只算分差的评估函数会让 bot 永远学不会塌缩。

配套的风险（对应 §3 的局限 3）：塌缩会把那 k 张牌**公开**进弃牌堆，等于告诉全场你手里留下了什么。`r`（多张替换冒险）参数控制的是"是否在非已知同点的情况下也赌一把"——错配时被选中的牌不会被移除，反而插入持牌（+1 张），选 3–4 张还额外插入罚牌（+2 张），并触发位置整体偏移。

另外，`MISMATCH_PENDING` 阶段的 `left`/`right` 选择不是对称的：`insertAtEnd` 中 `right` 走 `push`（保留位置 1..n 不变），`left` 走 `unshift`（平移全部位置）。所以**永远选 `right`**，罚牌同理。

## 七、参数到人格维度的映射

五个维度，每个维度由 1–3 个参数聚合而成：

| 人格维度 | 构成参数 | 玩家可感知的表现 |
| --- | --- | --- |
| **风险偏好** | `k`（主）、`β`、`r` | 什么时候喊 Cabo、输多少 +5 |
| **信息掌控** | `m`、`c`、`ρ` | 是否"记牌"、换牌是否精准 |
| **攻击性** | `a`、`t`、`d` | 换牌频率、是否专门搞某个人 |
| **节奏与耐心** | `g`、`u`、`L` | 出牌快慢、落后时是否翻脸变激进 |
| **拟人瑕疵** | `ε`、`chattiness`、`tilt` | 会不会犯错、像不像真人 |

**重要提醒：** 玩家实际感知到的"性格"，主要来自**风险偏好 + 攻击性 + 节奏 + 瑕疵**这四项，而不是完整的 13 个参数。调参时应该优先打磨这四个可感知维度，`m`、`c`、`ρ` 这类参数影响的是"强不强"，玩家基本无感。

## 八、Bot 人设卡

### 人设 1 · 算盘（Abacus）——精算保守型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 2.2 | −0.05 | 1.0 | 1.0 | 0.5 | 0.4 | 0.4 | 0.7 | 0.05 | 0.01 | 0.3 | 0 |

- **性格特征**：只在数学上极有把握时才喊 Cabo（需要 2.2 倍安全边际，即 `H=15` 时要 55% 胜率）。几乎不犯低级错误，稳步把分数压到最低。
- **配置思路**：`k` 拉高是核心；`ε` 压到 0.01 保证"可靠"；`r` 压到 0.05 避免错配罚牌（错配会让手牌涨到 5–6 张，是纯亏损）。
- **适用场景**：默认陪玩对手、教学局、"可预测的可靠基线"、Bot 天梯的强度参考线。

### 人设 2 · 赌徒阿豪（Gambler）——高风险激进型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 0.45 | +0.25 | 0.7 | 0.5 | 0.9 | 0.3 | 0.5 | 0.8 | 0.8 | 0.05 | 1.0 | 0 |

- **性格特征**：`k=0.45` 意味着只要胜率超过理论最优线的 45% 就敢喊——`H=20` 时只需 9% 胜率。会频繁宣告、频繁失败吃 `+5`，但偶尔一击制胜。喜欢赌多张替换。
- **配置思路**：`k` 压到 0.45 是核心；`β=+0.25` 让它系统性地低估未知牌（乐观）；`r=0.8` 让它敢在非已知同点时做多张替换；`u=1.0` 让它在落后时进一步加注。
- **适用场景**：娱乐局、需要制造戏剧性和翻盘感的对局、直播效果、惩罚过于保守的真人玩家。

### 人设 3 · 记忆大师（Mnemo）——完美记忆型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 1.0 | 0 | 1.0 | 1.0 | 0.6 | 0.6 | 0.5 | 0.6 | 0.15 | 0 | 0.5 | 0 |

- **性格特征**：`k=1.0` 恰好落在数学最优线上，加上完美记忆（`m=1`）和完整计数（`c=1`），宣告时机贴着理论最优。`ε=0` 意味着从不失误。决策快而精准。
- **配置思路**：全参数取"无偏 + 满分信息"。**建议在 assisted 记忆模式下运行**——经典模式下服务端不保存历史牌位，`knowledge.slots` 会被清空，`m=1` 也无法兑现。
- **适用场景**：高难度对手、Bot 强度上限基准、回归测试的参照物（任何新人设打不过它说明参数有问题）。

### 人设 4 · 搅局者（Gremlin）——攻击破坏型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 1.4 | 0 | 0.9 | 0.8 | 1.0 | 1.0 | 1.0 | 0.4 | 0.3 | 0.03 | 0.5 | 0 |

- **性格特征**：不以自己最低分为目标，而以"让别人难受"为目标。频繁用 9/10 偷看、11/12 交换，专门针对当前总分最低者（`t=1.0`），并且优先把高分牌塞给对方（`d=1.0`）。自己的分数未必最好。
- **配置思路**：`t=1.0` + `d=1.0` 是核心；`a=1.0` 让 swap 门槛降到最低；`g=0.4` 让它更依赖弃牌堆（因为弃牌堆顶往往是别人刚扔掉的高牌，塞回给对方很划算）。
- **适用场景**：多人局制造混乱、惩罚"纯记牌流"玩家、克制月神人设、增加博弈层次。注意它会**拖慢所有人的平均节奏**，不适合新手局。

### 人设 5 · 佛系老王（Chill）——新手陪玩型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 3.0 | −0.15 | 0.45 | 0.25 | 0.15 | 0.3 | 0.2 | 0.5 | 0 | 0.12 | 0.1 | 0 |

- **性格特征**：`k=3.0` 意味着几乎不主动宣告 Cabo（`H=10` 时要 100% 胜率才喊）。会忘牌（`m=0.45`）、不记牌堆（`c=0.25`）、失误多（`ε=0.12`）、决策慢（`L` 拉长）。玩家容易赢，但不至于无聊——因为它仍然会做基础的低级动作。
- **配置思路**：`k` 拉到 3.0 是核心；`m`/`c` 压低制造"凭感觉打"的观感；`ε=0.12` 提供可感知的失误。**注意不要把所有参数都调烂**——`a` 和 `r` 压低即可，`g` 保持 0.5 让它偶尔还有亮眼操作。
- **适用场景**：新手教学局、放松局、低压力陪玩、让玩家体验"赢的感觉"。

### 人设 6 · 月神（Moonchild）——极端目标型

| 参数 | k | β | m | c | a | t | d | g | r | ε | u | ω |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 取值 | 1.6 | +0.1 | 1.0 | 1.0 | 0.7 | 0.4 | 0.6 | 0.6 | 0.4 | 0.02 | 0.5 | 1.0 |

- **性格特征**：唯一目标是凑齐 2 张 Q + 2 张 K 触发 Shooting the Moon（本人计 0 分，其余玩家各计 `targetScore / 2`）。`ω=1.0` 时策略从"最小化自己的分"切换为"囤牌"：绝不弃 K、主动收集 Q、`k` 抬高（因为一旦喊了 Cabo 就没机会继续囤牌）。
- **配置思路**：`k=1.6` 而非更高，是权衡——太保守会错过囤牌窗口，太激进会毁掉囤牌成果。**必须实现"月相检测"**：只有在手里已有 1 张 K 且剩余牌堆/弃牌堆中 Q 与 K 的可见度足够时才进入囤牌模式，否则回退到普通策略。
- **适用场景**：彩蛋型对手、高难挑战、直播效果。**不建议作为默认对手**——自然触发概率约 0.0022%（见 §3.4），绝大多数对局它只是在乱打，体验会很差。
- **配套玩法**：由于 moon 判定发生在 `scoreRound()` 且**优先于** Cabo 判定，其他 bot 应该具备"反月神"逻辑：发现有人囤 K 时，优先抢走 Q（搅局者人设天然具备这个行为）。

## 九、评估与调参

**自对弈回归。** 用 `deck.ts` 的 `seededRandom(seed)` 固定随机源，保证对局可复现。4 人桌，每个座位轮换人设，跑 N 局后统计：

- 平均每轮得分（越低越好）
- Cabo 宣告频率与成功率（`k` 是否合理）
- 严格最低率（`p̂` 估计是否校准——把 `p̂` 分桶后看实际胜率是否落在桶内，这是检验蒙特卡洛模型是否正确的关键指标）
- 胜率 / 相对 ELO

**样本量。** 单局手牌分标准差约 7.3，四人对局方差很大。要区分两个 `k` 值的强弱差异，**每对至少 1000 局**，否则结论会被噪声淹没。

**调参顺序。** 先固定 `m=c=1, ε=0` 求"强度上限"，扫 `k ∈ {0.5, 0.75, 1.0, 1.5, 2.0, 2.5, 3.0}` 找最优；再在最优 `k` 附近微调 `β` 和 `ρ`；最后才加 `ε` 和 `L` 做拟人化。**不要一开始就把 13 个参数一起调。**

**防过拟合。** 评估必须在**混合人设池**里做，不能只跟同一个人设对打——否则会出现"专克自己"的假强度。

### 9.1 实测结果（实现阶段回填）

`p̂` 校准，1500 局混合人设（`abacus,gambler,mnemo,gremlin`，服务端时间轴无抖动）：

```
校准误差（样本加权 ECE）= 2.7%   最大偏差 = 6.8%   门槛 5%
```

等量分桶逐段（预测 → 实际）：14.1→16.2、19.0→20.6、22.5→23.9、26.3→26.9、
31.4→32.3、39.8→43.2、48.2→53.0、55.5→62.3、63.4→67.9、**78.0→78.8**。

**残余偏差是"轻微悲观"**（中段 +3~7%），高 `p̂` 段已经校准到 ±1%。方向很重要：模型宁可低估自己，也不会在最有把握的时候虚报胜率——后者正是"机器人做出人类看不懂的宣告"的来源。

人设行为差异，1500 局同桌：

| 人设 | 胜率 | 平均每轮分 | 宣告/局 | 宣告成功率 | 宣告时 p̂ | 宣告时阈值 |
| --- | --- | --- | --- | --- | --- | --- |
| 算盘 | 25.2% | 13.28 | 0.43 | 73.7% | 71.1% | 61.0% |
| 赌徒阿豪 | 15.6% | 15.14 | 3.55 | 26.4% | 24.8% | 17.9% |
| 记忆大师 | 35.1% | 12.65 | 1.59 | 56.2% | 52.3% | 36.9% |
| 搅局者 | 27.6% | 13.07 | 0.96 | 65.7% | 60.7% | 46.5% |

四人桌的"随机基线"是 25%。算盘/记忆大师/搅局者都在基线之上，赌徒在基线之下——这正是设计意图：赌徒的 `k = 0.45` 把门槛压到 p̂ 的自然下限（约 0.25）附近，等于**每一手都在宣告**，长期必然是负期望。它是"陪玩气氛组"，不是"强度角色"。

**M4 验收门槛**（赌徒宣告频率 > 算盘 3 倍）：实测 **3.55 / 0.43 = 8.3 倍**，通过。

**M5 验收门槛**（记忆大师 vs 3×佛系老王 > 70%）：**71.9%，通过**——但有一个前提值得单独记一笔。

同一配置（1000 局、同种子、只改蒙特卡洛采样数）：

| 采样数 | 记忆大师胜率 | 每局宣告次数 | 宣告成功率 |
| --- | --- | --- | --- |
| 150 | 69.1% | 6.37 | 48.2% |
| **400** | **71.9%** | 6.37 | 49.2% |

**采样数本身就是强度参数。** 原因是**选择偏差**：`p̂` 是 `N` 次采样的频率，标准误约 `sqrt(p(1−p)/N)`（`N = 150`、`p̂ ≈ 0.8` 时约 3.3%）。宣告条件是 `p̂ ≥ 门槛`，于是"p̂ 偏高"的噪声被系统性选进来——边缘宣告比模型以为的更容易失败，bot 略微过度宣告、胜率被压低。采样数翻 2.7 倍把标准误压到约 2%，选择偏差随之减半。

这是第 14 个可调参数，也是唯一一个**调大只有好处、代价只是 CPU** 的参数。线上默认取 300。

**残余的建模缺口（已定位，未修）**：高 `p̂` 段的失败仍以**平局**为主。记忆大师会用 2~4 分的极低手牌宣告，而低手牌总分是**高度离散**的小整数（0/1/2/4/…），对手撞上同分的概率远高于连续模型给人的直觉——而规则要求**严格**最低（`strictLowest: true, tieFails: true`）。修掉重洗缺口后该段校准偏差已从 −14.2% 收到 +0.7%（混合池），但"校准"和"胜率"是两个指标。若要进一步提强度，可给阈值加一个随 `H` 变小而增大的"平局边际"，属调参而非建模。

## 附：一句话总结

Cabo 的 bot 不需要机器学习，因为它的不确定性是"信息不完全"而非"策略爆炸"——而前者可以用未见牌池计数 + 蒙特卡洛采样精确逼近。真正的技术支点是那条闭式阈值 `P > (5 + δ) / (H + 5)`：它把"什么时候喊 Cabo"变成单个系数 `k`，而 `k` 连同攻击性、记忆保真、失误率几个参数，就足以拼出一整排性格分明、可解释、可单测的陪玩 bot。

代价也很清楚：这条闭式解**必须配合校准检验**才有意义。落地过程中被实测推翻的推导有一处、把校准带偏的建模坑有七个，全都不是"读代码能看出来"的——它们只在"把模型预测量和回合实际量并排打印"的时候才显形。**没有校准检验的规则 bot，就是一台自洽但错误的机器。**
